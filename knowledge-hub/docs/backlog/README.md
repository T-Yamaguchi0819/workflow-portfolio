# 機能追加バックログ

Knowledge Hub の機能追加バックログ。**1要件1ファイル**で管理し、着手時は ai-flow（`/ai-flow <タスク名>`）の [1]要件確認に「資料あり（本ディレクトリの該当ファイル）」として入力する。

- 本ディレクトリのファイルは**要件の素材**であり、Acceptance Criteria はここでは固定しない（AC はフローの [1] でユーザー承認を経て `要件.md` に固定する）
- 各ファイルの「仕様の方向性」は現時点の案。フローの [1][2] で確定・変更されうる
- 着手したら該当ファイルのステータスを更新する（未着手 → 進行中 → 完了）

## 一覧

| No | 要件 | ステータス | 依存 | 暫定規模 / リスク |
|----|------|-----------|------|------------------|
| [B-01](B-01_管理ユーザー.md) | 管理ユーザー（全記事の編集・削除が可能） | 未着手 | なし | L / **Critical**（認証・認可） |
| [B-02](B-02_記事パスワード管理.md) | 記事のパスワード管理（編集・削除の保護） | 未着手 | なし | M / High |
| [B-03](B-03_投稿者名表示.md) | 投稿者名の表示（任意入力） | 未着手 | なし | S〜M / Medium |
| [B-04](B-04_トップ表示固定.md) | 特定記事のトップ表示固定（管理ユーザーが設定） | 未着手 | B-01 | M / High |
| [B-05](B-05_コメント機能.md) | 記事へのコメント機能（パスワード保護つき） | 未着手 | B-02（B-01 があれば管理削除も） | L / High |

## 推奨着手順と依存関係

```
B-03 投稿者名 ──────────────┐ （独立・最小。肩慣らしに最適）
B-02 記事パスワード ──┬─────┤
B-01 管理ユーザー ────┼──→ B-04 トップ固定（管理者操作が前提）
                      └──→ B-05 コメント（パスワード方式を踏襲。管理削除は B-01 前提）
```

- **B-02 と B-01 は相互に補完する**: B-02 単独では「パスワードを知る人だけが編集・削除できる」、B-01 が入ると「管理ユーザーはパスワードなしで全記事を編集・削除できる」。どちらを先に入れてもよいが、後から入れた側で他方への影響（バイパス処理の追加）を要件に含めること
- B-01 は認証・認可のため **リスク Critical**（`project.yaml` の risk 分類）。独立レビューに加えて人間レビュー必須
