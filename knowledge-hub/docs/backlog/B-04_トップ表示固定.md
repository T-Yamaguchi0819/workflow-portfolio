# B-04: 特定記事のトップ表示固定（管理ユーザーが設定）

| 項目 | 内容 |
|------|------|
| ステータス | 未着手 |
| 種別 | 改善・機能追加 |
| 対象画面/機能 | S-01 記事一覧（表示順）・S-02 記事詳細（固定設定の操作） |
| 依存 | **B-01 管理ユーザー**（固定の設定・解除は管理ユーザーのみが行うため） |
| 暫定規模 / リスク | M / High（一覧の取得・ソートロジックと管理者権限に跨がる。GSI に触れる場合は High 確定） |

## 背景・目的

周知事項や重要なナレッジ（例: 全社向けのお知らせ、頻出 FAQ）を、更新日時順に埋もれさせず**一覧の先頭に固定表示**したい。乱用を防ぐため、固定の設定・解除は管理ユーザーのみが行える。

## 要件概要（ユーザー要望）

- 管理ユーザーが特定の記事を「トップ表示固定（ピン留め）」に設定できる
- 固定された記事は記事一覧の先頭に表示される

## 仕様の方向性（案・未確定）

- **データ**: `Article` に固定フラグ（例: `pinned: boolean`）を追加。固定記事群の並び順が必要なら固定日時も持つ
- **一覧の並び**: 固定記事を先頭に、以降は現行の並び（更新日時降順）を維持する。カテゴリ絞り込み（GSI `category-index`）併用時の挙動を決める必要がある
- **取得方法**: 固定記事の抽出を全件スキャン内のフィルタで行うか、GSI を追加するかは [2]Plan で判断。**GSI を追加する場合もプロビジョンドキャパシティの無料枠（合計 25RCU/WCU）内に収める**こと（オンデマンド化は禁止）
- **操作 UI**: S-02 記事詳細（または S-01）に管理ユーザーのみ表示される固定/解除ボタンを置く。API は認可必須（B-01 のセッション検証）
- **表示**: 固定記事にはピン留めを示すマーク等を表示する

## 影響範囲（想定）

- backend: `Article` 属性追加、固定設定 API（認可つき）、一覧のソートロジック
- frontend: S-01 の並び・固定マーク表示、固定/解除の操作 UI（Server Actions）
- infra: GSI を追加する場合は `template.yaml` とキャパシティ配分の見直し（**課金に影響する変更はリスク Critical 扱い**）
- docs: 設計書（機能・API・データ）、テーブル定義書、画面設計書（S-01/S-02）、README（API 仕様）

## ai-flow [1]要件確認で確定させる事項

- 固定できる記事数の上限（無制限 / 例: 3件まで）
- 複数固定時の並び順（固定した順 / 更新日時順）
- カテゴリ・タグ・キーワードで絞り込んだ場合も固定記事を先頭に出すか、絞り込み時は通常扱いにするか
- 固定操作の UI 配置（S-02 詳細のみか、S-01 一覧からも可能か）
- 固定記事の視覚表現（マーク・背景色等）
