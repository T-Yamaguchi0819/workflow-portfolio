# 画面設計書 S-03 記事作成

| 項目 | 内容 |
|------|------|
| 画面ID / 画面名 | S-03 / 記事作成 |
| パス | `/articles/new` |
| レンダリング | SSR + クライアントフォーム(`ArticleForm`、S-04 と共通コンポーネント) |
| 実装 | `frontend/src/app/articles/new/page.tsx` / `frontend/src/components/ArticleForm.tsx` / `frontend/src/lib/actions.ts` |
| 使用API | A-03 `POST /api/articles` |

## 1. 画面概要

新規記事を入力・登録する。送信は Server Action(`createArticleAction`)経由で行い、バリデーションエラー時はページ遷移せず同一画面にエラーを表示する(`useActionState`)。

## 2. 画面レイアウト

```
+--------------------------------------------------------------+
| ← 記事一覧に戻る                                              |
| NEW ／ 新規作成                                               |
| 記事を書く                                                    |
+--------------------------------------------------------------+
| (エラー時のみ) ▌入力内容に誤りがあります                      |
|               ・title: タイトルは必須です …                   |
| タイトル [必須]                                               |
| [                                              ]              |
| カテゴリ [必須]                  例: IT-FAQ / 総務 / 開発     |
| [                                              ]              |
| タグ                  カンマ区切りで最大10個 (例: VPN, …)     |
| [                                              ]              |
| 本文 [必須]                              Markdown が使えます  |
| [ textarea(等幅・320px〜・縦リサイズ可)              ]        |
|                                                               |
| [作成する] [キャンセル]                                       |
+--------------------------------------------------------------+
```

## 3. 入力項目定義

| # | 項目 | 種別 | 必須 | クライアント制約 | サーバー制約(Bean Validation) |
|---|------|------|------|------------------|-------------------------------|
| 1 | タイトル | input(text) | ○ | `required` / `maxLength=200` | 必須・200 文字以内 |
| 2 | カテゴリ | input(text) | ○ | `required` / `maxLength=50` | 必須・50 文字以内。前後空白はサーバーで除去 |
| 3 | タグ | input(text) | — | なし(自由入力) | カンマ(`,` または `、`)区切りで分割後: 最大 10 個・各 30 文字以内。空白除去・空要素除去・重複排除はサーバーで実施 |
| 4 | 本文 | textarea | ○ | `required` | 必須・50,000 文字以内。Markdown 原文のまま保存 |

制約の正はサーバー側(`ArticleRequest`)。クライアント制約は入力補助であり、突破されてもサーバーで 400 になる。

## 4. イベント定義

| # | トリガー | 処理 | 遷移先 |
|---|----------|------|--------|
| 4-1 | 作成するボタン | 送信中はボタン無効化+「保存中…」表示。formData → タグ分割・整形 → A-03 POST。成功時は一覧を revalidate | 成功: S-02 `/articles/{新規id}` |
| 4-2 | (4-1 の異常系) | 400: FormState にメッセージ+項目別エラーを格納し同一画面に表示(入力値は保持) / 接続不可: 「APIに接続できませんでした。…」を表示 | 遷移なし |
| 4-3 | キャンセル | 入力破棄(確認なし) | S-01 `/articles` |

## 5. メッセージ一覧

| 種別 | 文言 | 出所 |
|------|------|------|
| 見出し | 入力内容に誤りがあります | API(400 `message`) |
| 項目別 | `{field}: {理由}`(例「title: タイトルは必須です」) | API(400 `errors[]`。文言定義は `ArticleRequest` のアノテーション) |
| 接続エラー | APIに接続できませんでした。バックエンドの起動状態を確認してください。 | フロント(`actions.ts`) |
| 送信中 | 保存中… | フロント(`ArticleForm`) |
