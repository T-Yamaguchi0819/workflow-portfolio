# [8] 実績記録・ナレッジ化・完了

**目的**: タスクの実績を測定可能な形で記録し、得られた判断・失敗をナレッジへ還流してから完了する。**このフェーズが「案件をこなすほど基盤が賢くなる」サイクルの入口**なので、簡易版でも省略しない。

## 前提（最初に読む）

1. `_state.md`・対象 No の全成果物（要件.md〜verify.md/docs.md）
2. `.ai-flow/knowledge/precedents.md`・`defaults.md`
3. `.ai-flow/project.yaml`（`git.commit_format`・`git.commit_policy`・`git.commit_excludes`）

## 手順

### 1. 実績記録

`templates/実績.md` をコピーして `No{N}_{機能名}/実績.md` を作成し、**metrics ブロック（機械可読 YAML。集計の正）を必ず埋める**（人間工数・手戻り回数・初回PASS・人間による追加指摘等。分からない項目はユーザーに確認するか `null` とし、理由を特記事項に書く。推測値を入れない）。

**振り返りサイクル**: 記録後、完了タスク数が `evaluation.review_cycle` の倍数に達した場合は `python .ai-flow/evaluate_flow.py` でフロー評価レポートを生成し、完了ゲートで提示する（未達 KPI があれば要因と対策をユーザーと確認し、確定した対策は defaults/precedents へ還流する）。

### 2. ナレッジ化

- **判断の還流**: 本タスクで新たに確定した運用値は `defaults.md`（チーム共通）／`defaults.local.md`（個人・環境固有）へ、設計判断・記載慣行は `precedents.md` の判断履歴へ追記する
- **失敗の還流**: AI の誤り・見落とし・人間による修正があった場合、`precedents.md` の**失敗事例**節に「誤った理由／見落としたもの／人間の修正内容／今後の防止策」を記録する
- **ルール化の提案**: precedents.md を見渡し、**同種の失敗が3回**記録されていたら、`guards/guard-rules.json` への機械検査ルール追加（正規表現で検出可能な場合）またはフェーズ定義・roles への制約追記を**ユーザーに提案**する

### 3. 一時成果物の整理

恒久的に残すもの（要件・plan・review・verify・実績・確定した判断）と一時成果物（試行錯誤ログ・中間レビュー等）を区別し、一時成果物は削除候補としてユーザーに提示する（独断で削除しない）。

### 4. 完了ゲート（`git.commit_policy` でモード分岐）

コミットの共通規約（両モード）:

- `commit_format` に従う（本文に **Why** を必ず含める）
- `commit_excludes` の生成物を含めない
- pre-commit の guards 検査が ERROR を出した場合は解消してから再コミット（誤検知と考える場合も独断で回避せずユーザーに確認）

**manual の場合**: 全成果物の一覧・実績サマリ・未解決事項ゼロの確認をユーザーに提示し、**コミット要否を確認**する。

**auto の場合**（各フェーズで自動コミット済み。未コミット分をコミット・push してから）:

1. **PR 発行**: `templates/pr.md` を元に PR 本文を作成し（要件/AC・変更分類・リスク/規模・検証エビデンス・人間レビュアーの観点。`issue_sync` 有効時は `Closes #{Issue番号}` を含める）、`gh pr create` で発行する（`pr.base`・`pr.draft` に従う）
2. **AI PR レビュー**（`pr.ai_review: true` の場合）: [5] と同じコンテキスト分離（サブエージェント/別セッション）で、**PR の最終 diff 全体**を `roles/code-reviewer.md` の観点でレビューし、結果を PR コメントとして投稿する。**要修正**があれば修正・push して再実行する（差し戻し上限は [5] と同じ最大2往復。超えたら 🛑 エスカレーション）
3. **マージ承認待ち**: 全成果物の一覧・実績サマリ・PR の URL・AI PR レビュー結果をユーザーに報告して本フェーズを終了する。**マージは人間が行う。AI は自分の PR をマージしない**
4. **マージ後の還流**: 人間の PR レビューで指摘があった場合、件数・内容を `実績.md`（「AIレビュー後に人間が発見した問題数」）へ追記し、失敗事例は `precedents.md` へ記録する（マージ直後でも次タスク開始時でもよい）

### 5. Issue クローズ（`issue_sync` 有効時のみ）

- **manual**: 完了ゲート通過後、完了サマリ（実績サマリ・成果物一覧・ブランチ名）を `gh issue comment` で投稿してから Issue をクローズする
- **auto**: 完了サマリのコメントのみ行う（クローズは PR 本文の `Closes` によりマージ時に自動で行われる）

`gh` が使えない場合はスキップし、その旨をユーザーに報告する。

## 成果物

- `No{N}_{機能名}/実績.md`・ナレッジ追記（defaults / precedents）・（manual で指示があれば）コミット・（auto の場合）PR＋AI PR レビューコメント
