# [4] 実装（修正Plan の実行）

**目的**: 承認済み Plan に従って本実装を行う。役割定義は `.ai-flow/roles/coder.md` に従う。

## 前提（最初に読む）

1. `_state.md`・対象 No の `要件.md`・`plan.md`・`test.md`
2. `.ai-flow/roles/coder.md`（実装者の役割定義・コーディング原則）
3. `.ai-flow/project.yaml`（`constraints`・`build.compile_command`）

## 手順

1. Plan の対象ファイルを順に修正する。**変更は Plan の範囲に限定**し、Plan に無い変更が必要と判明した場合は独断で広げず、Plan を更新して未解決事項として返す（差分と無関係な既存コードの整形・改善をしない）
2. **変更禁止リストに触れていないこと**を修正のたびに確認する（plan.md の変更分類が正）
3. 実装原則（roles/coder.md）:
   - 既存コードのパターン・スタイル踏襲を最優先（独自の抽象化・新しいイディオムを持ち込まない）
   - 仮実装禁止（ダミー値・見せかけ再現をしない）
   - `project.yaml` の `constraints`（禁止/必須/事故多発ポイント）を遵守
4. **自己チェック**: コンパイル/ビルド（`compile_command`）を通し、`python .ai-flow/guards/verify_diff.py --repo <対象リポジトリ>` で禁止パターン検査を実行して ERROR 0 件を確認する（コミット時にも pre-commit で強制されるが、ここで早期検知する）
5. [3] のテストを実行し、結果を記録する（PASS が完了条件。失敗が残る場合はその内容と原因分析を記録）
6. `No{N}_{機能名}/impl.md` に、変更ファイル・変更内容・自己チェック結果・迷った判断を記録する

**注意**: `impl.md` は [5]独立レビューではレビュアーに**渡さない**ファイルである（実装者の解釈をレビュアーに引き継がないため）。ただし記録は省略しない（[8]ナレッジ化と人間の監査に使う）。

## 成果物

- 実装コード（対象リポジトリ）
- `No{N}_{機能名}/impl.md`

## 完了条件

- Plan の全項目が実装済み・スコープ外変更なし
- コンパイル/ビルド成功・guards 検査 ERROR 0 件・[3] テスト PASS
