# /ai-flow — AI修正フロー統括（Claude Code）

**まず `.ai-flow/FLOW.md` と `.ai-flow/project.yaml` を読み、FLOW.md の統括手順に厳密に従うこと。** 本ファイルは Claude Code 固有の実行方法だけを定める。

**対象**: $ARGUMENTS

## 実行手順

1. **状態の確認**: `{work_dir}/{タスク名}/_state.md` を読む。無ければフェーズ0から、あれば進捗マトリクスの未完了の最初のフェーズから再開する
2. **フェーズ毎にサブエージェントを起動**: 下表の推奨エージェントで Agent を起動し、次の指示を渡す:
   > `.ai-flow/flow/{フェーズ定義ファイル}` を読み、その手順を厳密に実行せよ。対象タスク=`{タスク名}`、対象要件=`{No指定があれば}`、作業ディレクトリ=`{work_dir}/{タスク名}/`。あなたはユーザーと直接対話できない。フェーズ定義に「ユーザーに確認/承認」とある事項は、推測で進めず**未解決事項として返して終了**すること（回答済みの事項は `_state.md` の「解決済みの確認事項」を参照）。完了後、生成・更新したファイルと未解決事項を簡潔に返すこと。

   | フェーズ | 推奨エージェント |
   |---------|----------------|
   | 0 初期化／1 要件・AC／2 Plan／7 ドキュメント | general-purpose |
   | 3 テスト先行作成 | test-writer |
   | 4 実装／6 動作確認 | coder |
   | 5 独立レビュー | **code-reviewer**（コード）＋必要に応じ **test-reviewer**（テスト） |
   | 8 実績・ナレッジ化 | general-purpose |

3. **[5]独立レビューのコンテキスト分離**: code-reviewer へは **要件.md・plan.md・diff・`.ai-flow/roles/code-reviewer.md`** のみを指示で渡す。`impl.md` と実装時の経緯は**渡さない**（FLOW.md の分離ルール）
4. **ゲートで停止**: FLOW.md のゲート定義（AC承認・Plan承認・レビュー後・ドキュメント前・完了時）で必ずユーザー承認を得る。確認事項はゲートまで貯めて AskUserQuestion で一括確認し、defaults 適用分は事後報告に回す
5. **回答の受け渡し**: ユーザーの回答・承認は `_state.md` の「解決済みの確認事項」へ追記してから次のサブエージェントを起動する
6. **コミットは `git.commit_policy` に従う**: `manual` ならユーザー明示指示時のみ（PreToolUse フックでも強制される）、`auto` ならフェーズ完了ごとに自動コミット・push（最終承認は PR マージ。マージは人間が行う）

## 単独実行

特定フェーズだけ実行したい場合は「`.ai-flow/flow/{N}-*.md` を単独実行」と指示すればよい。各フェーズは `_state.md` と前フェーズ成果物から状態を復元して動作する。
